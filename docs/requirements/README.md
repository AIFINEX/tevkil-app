# Requirements

Versioned requirement documents. Each iteration produces a new file rather than overwriting the previous one — the Git history alone is not enough; future readers need to see the requirements as they were at a point in time.

## Naming

```
YYYY-Q[1-4]-<slug>.md
```

Examples:

- `2026-Q2-mvp.md`
- `2026-Q3-multi-tenant.md`

## Format

Each requirements doc should include:

- Goals (what success looks like)
- Non-goals (what we are NOT doing)
- User stories or use cases
- Acceptance criteria
- Open questions
- Status (draft / agreed / superseded by …)
